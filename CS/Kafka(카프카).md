# Kafka
- 대용량 데이터를 빠르게 전달하기 위한 메시지 큐 시스템
- A 서비스가 데이터를 보내면 Kafka가 중간에서 받아두고 B 서비스가 나중에 가져가는 구조 (우체통, 택배 물류센터 같은 역할)
- 데이터를 바로 처리하지 않아도 됨
- 일단 쌓아두고 나중에 처리 가능
- 여러 Consumer가 동시에 가져갈 수 있음

----

## 작동원리
- Producer → Kafka → Consumer
- 🔹 Producer : 데이터를 보내는 쪽 (예: 게시글 작성 이벤트 발행)
- 🔹 Kafka : 데이터를 저장해두는 중간 저장소
  - Topic이라는 단위로 관리
  - 데이터는 로그 형태로 쌓임
- 🔹 Consumer : 필요할 때 데이터를 가져가는 쪽 (예: 알림 서비스가 이벤트 소비)

----

## REST 대신 Kafka 쓰는 이유
- REST : A → B (즉시 응답 필요) / 동기 방식
  - 바로 응답 필요, 강한 결합, 장애 전파 쉬움
- Kafka : A → Kafka (일단 던짐) B는 나중에 가져감 / 비동기 방식
  - 나중에 처리 가능, 느슨한 결합, 장애 격리 가능

## 장점
1. 서비스 간 결합도 낮음 : 게시글 서비스가 알림 서비스 존재 몰라도 됨
2. 대용량 처리에 강함 : 로그 기반 구조라 처리량이 큼
3. 장애 전파 방지 : Consumer가 죽어도 Producer는 영향 없음
4. 확장성 좋음 : 파티션 기반으로 수평 확장 가능

----

## 단점
1. 구조가 복잡함 : Zookeeper, Broker, Topic 등 개념 많음
2. 운영 난이도 있음 : 모니터링, 장애 대응 필요
3. 데이터 중복 처리 고려 필요 : at-least-once 특성 때문에 멱등성 처리 필요

----

## Kafka를 쓰기 적합한 환경
- 이벤트 기반 구조 (게시글 작성 → 알림 발송)
- 로그 수집
- 대용량 데이터 스트리밍
- 서비스 간 비동기 통신
- MSA 환경

----

### 정리
- Kafka는 서비스 간 비동기 이벤트 전달을 위한 분산 메시지 시스템이며,
- 대용량 데이터 처리와 서비스 간 결합도 감소가 필요한 상황에서 사용합니다.
