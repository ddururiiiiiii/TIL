# 트래픽 급증 시 대응 방법


## 🔹 1단계: 원인 분석
- APM / 모니터링으로 병목 확인
  - CPU / 메모리 부족 (서버 리소스 문제)
  - DB 병목
  - 특정 API에 요청 

----

### 1️⃣ CPU / 메모리 부족 (서버 리소스 문제)
- 👉 이 경우는 애플리케이션 레벨 문제

#### 🔍 원인
- 애플리케이션 연산 과다
- GC 과다 발생
- 스레드 블로킹
- 트래픽 자체 증가

#### 🛠 대응
✅ 단기
  - 서버 수평 확장 (Scale-out)
  - 오토스케일링
  - 불필요한 로그/연산 제거

✅ 중기
  - 코드 최적화
  - GC 튜닝
  - 비동기 처리 도입

----

### 2️⃣ DB 병목
👉 이건 데이터 접근 레벨 문제

#### 🔍 원인
- 슬로우 쿼리
- 인덱스 미적용
- N+1 문제
- 커넥션 풀 부족
- Lock 경합

🛠 대응
✅ 단기
  - 커넥션 풀 조정
  - 캐시 적용 (Redis)
  - 읽기/쓰기 분리

✅ 구조 개선
  - 인덱스 설계
  - 실행계획 분석
  - 쿼리 리팩토링
  - 트랜잭션 범위 축소

----

### 3️⃣ 특정 API에 요청 집중
- 👉 이건 엔드포인트 단위 문제

🔍 원인
- 인기 API (예: 랭킹, 홈 화면)
- 무한 재시도 로직
- 봇 트래픽
- 특정 이벤트

🛠 대응
✅ 보호 전략
  - Rate Limit
  - 캐시 전면 적용
  - CDN 활용
  - API 응답 단순화

✅ 구조적 대응
  - 비동기 전환
  - 큐잉 처리
  - 서킷 브레이커 적용
